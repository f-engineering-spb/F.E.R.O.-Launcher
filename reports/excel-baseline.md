# Excel baseline — скорость, содержимое, отзывчивость (без исправлений)

Замерено 2026-10-05 внешним секундомером на копии реальной рабочей книги.
Оригиналы не изменялись. Оптимизация не начиналась.

## Версия

- Ветка: `chore/review-channel`, SHA `3e8fc65` (замерный код Excel идентичен
  `main`/`fix/word-png-integration` — движок Excel этими ветками не менялся).
- Сервер замеров: рабочий лаунчер, порт 8780 (тот же код Excel).

## Образец

- Формат XLSX, ~853 КБ, 5 листов (до ~1000 строк × ~74 столбца).
- Также в папке: 1 XLS (~36 КБ, legacy) и 1 маленький XLSX (2 листа) — не измерялись.
- XLSM отсутствует.

## Фактический маршрут (проверен по коду, не по комментариям)

- Список листов: быстрый парсинг `xl/workbook.xml` без загрузки книги (~22 мс).
- Открытие книги: первый запрошенный лист готовит ВСЮ книгу за один разбор
  openpyxl (`ensure_workbook_rendered`), остальные листы — фоновый прогрев
  уже готового дискового кэша.
- Миниатюра и большой просмотр: один и тот же кэшированный HTML листа
  (карточка — уменьшенный viewport того же HTML).
- Переключение листа: чтение готового HTML с диска.
- XLS в живом маршруте идёт через конвертацию Excel COM в XLSX
  (`excel_preview_source`); отдельный xlrd-путь существует только
  для маршрута `/api/preview` (диспетчер).
- `renderMs` в манифесте НЕ включает загрузку книги openpyxl.

## Подтверждённые дефекты

1. Формулы без кэшированных значений Excel показываются ПУСТЫМИ:
   все 3572 ячейки с формулами образца не имеют stored-значений
   (`data_only=True` их не видит), в HTML — пустые клетки вместо чисел.
2. Уведомление об обрезке/режиме пользователю НЕ показывается:
   параметр `notice` в `render_sheet_page` принимается, но в страницу
   не вставляется (лимиты 2000 строк / 100 столбцов действуют молча).
3. Скрытые столбцы с данными исключаются молча: в образце 4 скрытых
   столбца содержат десятки непустых клеток; предупреждения нет.
4. Числовые форматы не применяются: денежные/процентные форматы тысяч
   клеток отображаются сырыми числами (проверено по категориям форматов).

## Проверено как «нет в образце»

Даты, проценты как значения, изображения/диаграммы, содержимое за
пределами 2000 строк / 100 столбцов, XLSM. Объединённые ячейки есть
(174 диапазона → 144 colspan + 26 rowspan в HTML) — корректны.

## Отзывчивость

Во время 8.3-секундной подготовки книги `/api/health` отвечал 200
пятнадцать раз, сбоев ноль. Это не доказательство отзывчивости окна.
Для ручной проверки оставлена неоткрытая копия (имя сообщено отдельно);
её кэш пуст, преобразование заранее не запускалось.

## Ограничения и предложения

### Уточнение времени первого просмотра (E03)

453 мс запроса первого листа в таблице выше измерены ПОСЛЕ подготовки
книги (~8.3–8.7 с `/api/excel/workbook`). Это не время первого
просмотра. Полное время первого просмотра = подготовка книги + чтение
готового HTML листа. Повторный тёплый запрос — десятки миллисекунд
(пример: 46.9 мс).

### E01 — значения формул (копия, Excel COM, без макросов)

- Копия открывалась в установленном Excel только для чтения,
  без обновления внешних связей (UpdateLinks=0), с принудительно
  отключёнными макросами; макросы не запускались, внешние источники
  не обновлялись; оригинал не сохранялся.
- Внешних ссылок нет: LinkSources пуст, внешних связей в структуре
  книги нет; подключений нет (0, частей подключений нет); макросов
  нет (HasVBProject=False, частей VBA нет). Формат XLSX макросов
  не содержит по построению.
- Все 5 листов видимы. Областей печати нет. Расчёт при открытии
  включён (fullCalcOnLoad).
- 3572 формулы — внутренние ссылки между листами и ячейками книги.
  После пересчёта в Excel: 2842 дают числа, 730 — пусто как ссылки
  на пустые клетки, 0 ошибок. Текстовых результатов нет.
- Вывод: корректный просмотр — числа там, где их показывает Excel,
  пусто там, где пусто в Excel. Текущий HTML показывает пустыми все
  3572 клетки, то есть теряются 2842 числовых значения. Пустые 730 —
  корректная пустота, а не ошибка.

### E02 — эталон Excel → PDF (существующий механизм, без изменений)

- Проверен существующий скрипт `scripts/convert_excel_to_pdf.ps1`
  без изменений, на той же копии, с исходными настройками печати.
  Настройки книги молча не менялись.
- Настройки печати (только чтение): книжная ориентация везде;
  области печати не заданы (экспорт полного использованного
  диапазона); первый лист — вписать в 1 страницу, остальные —
  вписать по ширине. Обрезки областями печати нет.
- Замеры раздельно (один прогон скрипта + диагностический прогон
  в том же режиме): запуск Excel ~1.7 с; открытие копии ~0.7–0.8 с;
  пересчёт ~0.02–0.05 с; экспорт PDF ~18 с; сквозное время скрипта
  ~28 с (включая служебные паузы скрипта). Открытие измерено от
  `Workbooks.Open` до возврата; пересчёт — `Application.Calculate`.
- Результат: PDF ~1.2 МБ, 14 страниц из 5 видимых листов.
  PNG созданы существующим механизмом `engine_dwg_pdf` локально:
  все страницы 150 dpi и одна первая страница 300 dpi. Файлы
  хранятся только локально.
- Постраничное соответствие листам — только визуальным сравнением
  пользователем; наличие PDF полноту данных не доказывает.

### E03 — синтетические проверки (искусственные книги, без данных клиента)

Добавлены в `tests/test_excel_baseline.py`, класс
`ExcelBaselineLosses` (6 тестов всего, все проходят локально):

1. Формула без сохранённого значения (`=A1*2`) — HTML показывает
   пустую клетку вместо результата.
2. Процент (`0.5` + `0%`) и деньги (`1234.5` + `#,##0.00`) —
   видно сырые `0.5` / `1234.5`, форматированных `50%` / `1,234.50`
   нет.
3. Превышение лимита строк — метаданные `limited=True`, но блока
   предупреждения (`class="notice"`) в HTML нет.
4. Превышение лимита столбцов — обрезано до 100 столбцов молча
   (`limited=False`, предупреждения нет).
5. Намеренно скрытый столбец — исключён из HTML без предупреждения;
   само скрытие ошибкой не считается.

Факты по образцу для контекста: скрытых столбцов с данными — 4
(по одному на четырёх листах, десятки непустых клеток в каждом);
предупреждения нет. Нечисловых форматов в образце три вида:
`#,##0.00` (тысячи клеток), `@` (~тысяча), `0.00` (единицы);
процентного формата в образце нет — он покрыт синтетикой.
Параметр `notice` в страницу не вставляется (есть только CSS-класс),
проверено по коду оболочки.
