# Контракт нативного открытия файлов (NATIVE FILE OPENING CONTRACT)

Статус: **ЗАМОРОЖЕН (FROZEN)**. Любые изменения требуют явного подтверждения пользователя.

---

## 1. Назначение и контекст
F-Engineering Launcher предоставляет пользователю возможность быстрого просмотра и нативного открытия файлов рабочих чертежей и документов (.dwg, .dxf, .pdf, .docx, .xlsx и др.).

Данный документ фиксирует нерушимый контракт приоритетов, валидации и запуска файлов через нативные приложения операционной системы Windows.

---

## 2. Иерархия приоритетов (Strict Contract)

При вызове нативного открытия любого файла (`POST /api/open-file` с `action: "native"` или `action: "default"`):

### Приоритет A: Валидный EXE, явно сохранённый пользователем в Параметрах
Если для нормализованного расширения файла (например, `.dwg`, `.pdf`, `.docx`, `.xlsx`):
1. Опция `useNativeApps` включена (`true`).
2. В конфигурации указан непустой путь к исполняемому файлу.
3. Указанный путь существует на диске и является файлом (`Path(clean_exe).is_file() == True`).

**Поведение:**
- Запускается **ТОЛЬКО** этот исполняемый файл.
- Передаётся оригинальный путь к файлу отдельным аргументом списка: `[resolved_exe, resolved_file]`.
- Рабочей директорией (`cwd`) процесса устанавливается папка открываемого файла (`file_dir`).
- Запуск осуществляется через `ShellExecuteW("open", resolved_exe, f'"{resolved_file}"', file_dir, SW_SHOWNORMAL=1)` или `subprocess.Popen([resolved_exe, resolved_file], cwd=file_dir, creationflags=DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP)`.
- **СТРОГО ЗАПРЕЩЕНО:**
  - Использовать Windows default fallback.
  - Подменять приложение на AutoCAD, DWG TrueView, AcLauncher, accoreconsole или любой autodetect-кандидат.
  - Использовать `cmd.exe /c start` со склеиванием строк.
  - Использовать `shell=True`.

---

### Приоритет B: Настройка для расширения отсутствует или пуста
Если пользователь не настраивал приложение для данного типа файла, либо поле в «Параметры → Приложения» очищено:

**Поведение:**
- Используется системная ассоциация Windows (Shell fallback).
- Запуск эквивалентен двойному клику по файлу в Проводнике Windows (`explorer.exe`).
- Вызывается `ShellExecuteW("open", resolved_file, "", cwd, SW_SHOWNORMAL=1)` либо `os.startfile(resolved_file)`.
- Если у пользователя в Windows по умолчанию с DWG ассоциирован DWG Viewer — откроется DWG Viewer. Если AutoCAD — откроется AutoCAD.

---

### Приоритет C: Настройка заполнена, но EXE не существует или недоступен
Если в настройках указан путь (например, перенесённый профиль, удалённая программа, опечатка), но файл не найден на диске:

**Поведение:**
- **ЗАПРЕЩЁН ТИХИЙ FALLBACK.** Никакого молчаливого переключения на системную программу по умолчанию.
- Сервер возвращает структурированную ошибку HTTP 400:
  ```json
  {
    "ok": false,
    "error": "Для файлов DWG указано недоступное приложение. Проверьте Параметры → Приложения.",
    "error_code": "configured_app_missing",
    "details": {
      "extension": ".dwg",
      "configured_app": "C:\\Program Files\\...\\app.exe"
    }
  }
  ```
- Фронтенд перехватывает код `configured_app_missing`:
  1. Отображает пользователю понятное уведомление: *«Для файлов {EXT} указано недоступное приложение. Проверьте Параметры → Приложения.»*.
  2. Автоматически открывает модальное окно «Параметры» и фокусирует поле ввода для данного расширения.

## 3. Автоопределение программ Windows (Autodetect Rules)

Кнопка «Определить из Windows» в окне Параметров:
1. **Защита ручных настроек:** если в форме уже заполнены пути, система обязана запросить подтверждение пользователя (`confirm(...)`) перед перезаписью.
2. **Запрет AcLauncher.exe:** `AcLauncher.exe` и `ZwLauncher.exe` являются служебными диспетчерами ассоциаций оболочки Autodesk/ZWCAD и не могут быть вызваны как самостоятельные программы просмотра с аргументами.
   - Autodetect **СТРОГО ФИЛЬТРУЕТ** `aclauncher.exe` и `zwlauncher.exe`.
   - Если в реестре найден только `AcLauncher.exe`, поле `.dwg` остаётся пустым, а пользователю выводится подсказка: *«Для DWG укажите прямой путь к DWG Viewer или AutoCAD через «Обзор…»»*.

---

## 4. Изоляция от фоновых пайплайнов рендеринга

Нативное открытие файла полностью изолировано от:
- `accoreconsole.exe` и AutoCAD Core Console скриптов экспорта.
- Пайплайна предпросмотра Model Space и Layout Space.
- Ленты миниатюр и генерации PNG/PDF-кэша.
- Кнопки «Загрузить» (`/api/choose-folder` и Windows Forms `FolderBrowserDialog`).

---

## 5. Нормализация расширений и путей

- Все расширения нормализуются к нижнему регистру с ведущей точкой (`normalize_file_extension`):
  - `.DWG` -> `.dwg`
  - `DWG` -> `.dwg`
  - `dwg` -> `.dwg`
  - `.dwg` -> `.dwg`
- Все пути к файлам разрешаются до абсолютных нормализованных путей (`os.path.normpath(str(path.resolve()))`).
- Аргументы передаются строго списком `[exe, file]`, исключая проблемы с кириллицей, пробелами и скобками в путях.
