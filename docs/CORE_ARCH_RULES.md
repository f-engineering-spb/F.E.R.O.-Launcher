# Фундаментальный кодекс рендеринга (CORE ARCH RULES) v1.0

Статус: **обязателен к исполнению**. Любой новый код превью идет в
`app/rendering/` и подчиняется этим правилам. Исключения — только отдельным
решением с записью в `docs/DECISIONS.md`.

## R1. DWG / PDF — строго 150 DPI PNG

- Растр страниц: **только PNG через PyMuPDF (fitz)**, эталон —
  `app/rendering/engine_dwg_pdf.py` (`PREVIEW_DPI = 150`).
- **Полный запрет WebP в тракте генерации**: кодирование WebP в Pillow
  медленнее PNG в 2–5 раз по CPU (замер 09.2026) и не дает выигрыша
  скорости показа. WebP допустим только как выдача готового кэша, не синтез.
- **300 DPI по умолчанию запрещены**: дефолт среза DWG — `DWG_PREVIEW_DPI = 150`
  (`/api/dwg/model-page`). Явный `dpi` клиента 72–600 уважаем (HiDPI-зум),
  молчаливый дефолт 300 — нет.
- Конвейер DWG: `scripts/render_dwg_smart.ps1` печатает **векторный** PDF
  полистно (`page_0001.pdf` + склейка fitz/pypdf, accoreconsole — только
  fallback), растр — постранично в fitz.
- Кэш **атомарно-постраничный**: `runtime/cache/{pdf,dwg}/<key>/page-{N}.png`
  + `manifest.json`. Сбой/листание не пересчитывают готовые страницы:
  каждый файл проверяется независимо (`exists + size > 0`).

## R2. EXCEL — один разбор, мгновенные вкладки

- Книга XLSX/XLSM разбирается **1 раз при открытии** (openpyxl, full load),
  все листы рендерятся пакетно: `app/rendering/engine_excel.py`.
- Переключение вкладок — **дисковый/памятный кэш-хит без повторного разбора**
  (LRU открытых книг в процессе + `sheet-{N}-v10.html` на диске).
- **Запрещено**: полный `load_workbook()` на каждый клик вкладки (старая
  болезнь `server.py::excel_sheet_html`, ~6 с за клик).
- Старый бинарный **XLS (BIFF8) — только через xlrd (~10 мс), без COM**.
  COM для Excel — лишь legacy `.xls→xlsx` конвертация и PDF-фолбэк.
- Формулы читаются как кэшированные значения (`data_only=True`) везде одинаково.

## R3. WORD — первично HTML, COM только для .doc

- Первичный просмотр **DOCX — чистый HTML** через python-docx
  (`app/rendering/engine_word.py`): эталон — договор 35 стр. за ~1.2 с
  с сохранением пунктов, таблиц реквизитов и подписей.
- **Word COM (`convert_word_to_pdf.ps1`, таймаут 120 с) — только старые `.doc`**
  и pixel-perfect случаи. COM никогда не блокирует первичное превью.
- Быстрый путь отдается фронту отдельным маршрутом `/api/word/preview`
  (кэш `/cache/word/html/<key>/preview.html`).

## R4. РАСТРЫ И ТЕКСТ

- Фото (JPG/PNG/GIF) — Pillow, `app/rendering/engine_media.py`:
  **безопасный EXIF-поворот** (протухший тег, противоречащий уже портретному
  кадру `h > w`, игнорируется — кейс «Горяинов ВБ стр. 3»);
  кадры шире 1920px — даунскейл до Full HD, JPEG q85.
- TXT/LOG — **автодетект UTF-8 (BOM) → UTF-8 → CP1251**, вывод в безопасный
  `<pre>` с кликабельными `http(s)`-ссылками.

## R5. НАТИВНЫЕ ФОРМАТЫ — карточка-заглушка

- `.mpp .mov .mp4 .avi .mkv .zip .rar .7z .rvt .ifc .ppt …` превью **не строят**.
- Диспетчер (`app/rendering/dispatcher.py`) возвращает карточку `native_app`
  (имя, размер, `openAction: /api/open-file`), фронт показывает заглушку
  с кнопкой **«Открыть в программе по умолчанию»**.
- Исполнение открытия — только существующий `POST /api/open-file`
  (ShellExecuteW → `os.startfile`, контракт NATIVE_FILE_OPENING_CONTRACT).
  Дублирующие механизмы запуска запрещены.

## R6. ЕДИНЫЙ ШЛЮЗ

- Новая логика превью подключается через `dispatcher.get_file_preview()`
  и маршрут `POST /api/preview`. Прямые вставки рендер-кода в `server.py`
  запрещены — только тонкие шимы поверх движков.
- HTML-оболочка листа Excel (`_sheet_shell.py`) — побайтовый контракт
  с `app/frontend/app.js` (протокол `launcher-sheet-*`); менять только
  парой фронт+бэк.
