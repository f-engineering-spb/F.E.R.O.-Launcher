# Регламент выпуска обновлений Launcher v3 (Спринт 5)

Короткий цикл: `version.json` → тег → GitHub Actions → автообновление у пользователей.
Рабочая ветка: `dvg-main`.

## 1. Как выпустить новую версию

Шаг 1. Поднять версию в `version.json`:

```json
{ "version": "3.2.0", ... }
```

Шаг 2. Закоммитить:

```sh
git commit -am "release: bump to 3.2.0"
```

Шаг 3. Поставить тег и запушить (тег запускает workflow):

```sh
git tag v3.2.0
git push origin dvg-main --tags
```

Ручной запуск без тега: вкладка Actions → «Build & Release Launcher v3» → Run workflow.

## 2. Что произойдёт автоматически

1. Облако (windows-latest) соберёт PyInstaller EXE (`scripts\build_exe.cmd`).
2. Соберёт инсталлятор `dist_setup/FEngineering_Launcher_v3_Setup.exe` (Inno Setup 6).
3. Упакует лёгкий микро-патч `launcher-update-3.2.0.zip` (только `app + scripts + version.json`, без тяжёлого рантайма) и посчитает его SHA-256.
4. Опубликует GitHub Release `v3.2.0` с обоими файлами.
5. У пользователей лаунчер через 3 секунды после открытия покажет пилюлю «Доступно обновление v3.2.0 [Обновить]».
6. По нажатию лаунчер сам скачает патч (с проверкой SHA-256), сделает бэкап в `app_backup`, распакует поверх и перезапустится обновлённым.

## 3. Аварийный откат (Rollback)

- **Неудачная распаковка** — откат автоматический: `scripts/update_helper.cmd` восстанавливает `app` из `app_backup` и перезапускает лаунчер.
- **Ручной откат у пользователя** (если обновление встало криво): закрыть лаунчер, в папке установки выполнить `xcopy /E /I /Y app_backup app`, запустить снова.
- **Битый релиз для всех** — выпустить фикс-версию обычным циклом (раздел 1): поправить код, поднять версию (`3.2.1`), тег `v3.2.1`, push. Клиенты получат исправленный патч той же пилюлей.
- **Крайний случай** — полная переустановка: скачать `FEngineering_Launcher_v3_Setup.exe` из прошлого стабильного Release на GitHub и установить поверх (ставится без прав администратора).
